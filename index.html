S Language

为系统级 AI 训练而生的语言层。

IR 优先

S 的核心目标不是“语法炫技”，而是把训练、调度、内存和执行逻辑稳定地表达成 IR。

契约清晰

Tensor、Device、Dispatcher、Kernel、Autograd、Optimizer 分层明确，方便逐层实现与替换。

从小闭环开始

先验证标量训练、再验证最小 LoRA、最后扩展到 Qwen 级别训练，避免一开始就被大模型细节拖死。

NeurX Project

一个以 Runtime 为中心的 AI 框架。

项目目标

NeurX 试图把训练系统从“脚本拼装”提升到“契约驱动”的工程形态： 前端由 S 语言生成 IR，后端由 Runtime 执行，训练器、调度器和部署链路围绕同一套核心接口演进。

  • 接口冻结优先于功能堆叠
  • 先标量闭环，再扩展到 LoRA / SFT / Transformer
  • 训练、验证、保存、部署共享同一套思路

Founder

创始人：何书文

HSW

北京大学背景

何书文是 NeurX 与 S 语言的创始人，项目路线由他推动为“先运行时、后模型、再规模化”的工程策略。

详细介绍

何书文将系统语言、训练 Runtime、模型后训练和部署链路放在同一张架构图里审视。 在他的设计里，NeurX 不是单纯的训练脚本集合，而是一个从 S IR、设备抽象、Kernel 调度，到 mini trainer、LoRA 训练、验证与部署都可连续演进的统一系统。

这条路线的核心是：先把接口契约定稳，再把最小训练闭环跑通，最后逐步扩展到更复杂的模型与硬件后端。 这也是 NeurX 选择“runtime-first”而不是“feature-first”的原因。

Roadmap

从 Phase -1 到可用系统。

01

冻结契约

Tensor / Device / Kernel / Dispatcher / Autograd / Optimizer / Executor。

02

最小训练闭环

标量 forward、loss、backward、SGD，先确认 Runtime 的值语义。

03

最小 LoRA 版

从 2x2 或 4x4 矩阵开始，验证真实梯度更新和保存逻辑。

04

完整模型链路

扩展到 Qwen / Transformer 级别训练、验证和部署。
